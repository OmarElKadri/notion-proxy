FORMAT — first line inside the block is the tool name, then one `field: value` per line:

For any value that contains newlines, code, quotes, backslashes, or Windows paths, use a heredoc with a unique tag:

<tool_use>
Edit
file_path: path/to/file.py
old_string: <<<OLD
def hello():
    print("hi")
OLD
new_string: <<<NEW
def hello():
    print("hello, world")
NEW
</tool_use>

Rules:
- Heredoc opener is `field: <<<TAG`. The closing line must be exactly `TAG` on its own line, with no surrounding whitespace.
- Pick a TAG that does not appear inside the value (OLD, NEW, BODY, PATCH, EOF, etc).
- Do not JSON-encode inside heredocs. Write literal newlines, literal backslashes, literal quotes — exactly as they should appear in the file.
- Inline values (no heredoc) must fit on a single line and must not contain a literal newline.
- For array or object fields (such as MultiEdit `edits`, TodoWrite `todos`, Bash `command_lines`), put compact JSON inside a heredoc:

  edits: <<<EDITS
  [{"old_string":"foo","new_string":"bar"}]
  EDITS

- Boolean/number fields can be written as inline values like `replace_all: false` or `offset: 0`.
- Emit only one tool name per <tool_use> block. Emit multiple <tool_use> blocks if multiple calls are needed.
